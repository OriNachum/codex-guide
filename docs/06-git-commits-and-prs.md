# Git, Commits, and PRs in Codex Workflows

## Commit expectations

- keep commits scoped to the task
- use clear imperative messages
- avoid mixing refactors with behavior changes unless requested

## PR record expectations

A strong PR description includes:
- summary of changes
- validation commands and results
- caveats/limitations
- follow-up tasks (if any)

## Suggested commit message style

- `Add <feature> for <context>`
- `Fix <bug> in <module>`
- `Refactor <component> to <goal>`
- `Update docs for <topic>`
